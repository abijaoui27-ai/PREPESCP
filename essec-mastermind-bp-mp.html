Mastermind BP / MP

1. Objectif du chapitre

Dans un exercice de Mastermind, on cherche un code secret. On dispose de plusieurs propositions, et chaque proposition donne des indices : combien d'elements sont corrects, combien sont bien places, combien sont mal places.

Le but n'est pas de deviner. Le but est de transformer chaque ligne en information utile : element absent, element present, position possible, position impossible.

Idee centrale : chaque ligne est une contrainte. La solution finale est le seul code compatible avec toutes les contraintes.

2. Comprendre BP / MP

Ce chapitre n'a pas besoin d'une vraie partie par coeur. Il faut surtout comprendre le vocabulaire et savoir lire les indices correctement.

BP = bien place

L'element est dans le code et exactement a cette position.

MP = mal place

L'element est dans le code, mais il n'est pas a cette position.

Absent

L'element n'est pas dans le code du tout.

Contrainte

Une information qui limite les codes possibles.

Lecture d'un indiceBP / MP
Proposition : 3 7 9 - Indice : 1 BP / 1 MP

Deux chiffres parmi 3, 7, 9 sont dans le code. L'un est deja a la bonne place, l'autre est dans le code mais a une autre place. Le troisieme chiffre est absent.

3. Methode de surlignage

Pour ne pas se perdre, on utilise un code couleur simple. C'est la methode la plus propre pour les exercices courts comme pour les systemes plus longs.

Vert = BP certain

On garde l'element a cette position.

Orange = present mais mal place

On garde l'element, mais on barre/interdit cette position.

Rouge = absent

On elimine l'element de tout le code.

Crayon = hypothese

Quand on n'est pas encore sur, on note l'hypothese sans la figer.

Exemple de lecture visuelle

4
8
2
6
9

Ici, 4 est certain et bien place. 2 est present mais pas a cette place. 6 et 9 sont absents. Les cases non colorees restent a determiner.

Regle pratique : tant qu'un element n'est pas certain, on evite de le mettre en vert. Trop de certitude trop vite cree des erreurs.

4. Niveau superieur : le systeme de contraintes

Oui, le niveau au-dessus correspond exactement aux codes a 4 ou 5 chiffres avec plusieurs lignes. Dans ce cas, chaque ligne fonctionne comme une equation logique.

Code a 5 chiffressysteme
Code secret : _ _ _ _ _
LignePropositionIndiceCe que cela impose
11 2 3 4 51 BP / 1 MPDeux chiffres sont presents : un bien place, un mal place.
21 6 7 8 90 BP / 1 MPUn seul chiffre est present, mais pas a cette position.
30 2 7 4 92 BP / 0 MPDeux chiffres sont bien places. Les autres sont absents.
40 6 3 8 50 BP / 2 MPDeux chiffres sont presents, mais tous les deux mal places.

On ne peut pas traiter ces lignes isolement. Il faut les croiser : si une ligne donne une presence, une autre ligne peut interdire une position ou eliminer un chiffre.

Comment transformer les lignes en systeme

1
Presence

Pour chaque ligne, note combien de chiffres de la proposition sont dans le code.

2
Position

Separe ce qui est bien place de ce qui est seulement present.

3
Interdiction

Tout MP interdit la position de la ligne ou il apparait.

4
Verification globale

Une hypothese n'est valide que si elle respecte toutes les lignes du tableau.

5. Exemple corrige ligne par ligne

On prend un code a 3 chiffres pour comprendre la methode, puis on applique la meme logique aux codes a 5 chiffres.

Exerciceligne par ligne
LignePropositionIndice
A1 2 30 BP / 0 MP
B4 5 61 BP / 0 MP
C4 7 80 BP / 1 MP
D9 5 82 BP / 0 MP

Etape 1 - Ligne A

Ligne A : 1, 2, 3 donnent 0 BP / 0 MP. Donc 1, 2 et 3 sont absents. On les met en rouge partout.

Etape 2 - Ligne B

Ligne B : 4 5 6 donne 1 BP / 0 MP. Donc un seul chiffre parmi 4, 5, 6 est dans le code, et il est deja bien place. Les deux autres sont absents.

Etape 3 - Ligne C

Ligne C : 4 7 8 donne 0 BP / 1 MP. Donc un seul chiffre parmi 4, 7, 8 est present, mais il n'est pas a la place proposee. Si 4 etait bien place en position 1 dans la ligne B, alors la ligne C aurait au moins 1 BP avec le 4 en position 1. Impossible. Donc 4 n'est pas le BP de la ligne B.

Etape 4 - Retour ligne B

Comme 4 est impossible en BP, le BP de la ligne B est soit 5 en position 2, soit 6 en position 3.

Etape 5 - Ligne D

Ligne D : 9 5 8 donne 2 BP / 0 MP. Donc deux chiffres sont exacts et bien places. On voit que 5 peut etre en position 2. Cela confirme fortement 5 en position 2.

Conclusion pedagogique : on avance par allers-retours. On lit une ligne, puis on revient sur une autre. C'est exactement comme un systeme : chaque nouvelle information reduit les possibilites.

6. Methode finale a appliquer en test

1
Reperer les lignes a zero

0 BP / 0 MP = elimination totale. C'est toujours la premiere chose a chercher.

2
Surligner

Rouge pour absent, orange pour present mal place, vert pour bien place certain.

3
Comparer les lignes proches

Quand deux lignes se ressemblent, le chiffre qui change explique souvent la difference d'indice.

4
Construire le tableau des positions interdites

Pour chaque MP, noter : ce chiffre existe, mais pas ici.

5
Tester les hypotheses restantes

Une hypothese doit etre verifiee sur toutes les lignes, pas seulement sur celle qui l'a produite.

6
Valider le code final

Reprendre toutes les propositions une par une et verifier que les BP / MP tombent exactement.

7. Pieges classiques

  • Piege 1 : croire qu'un MP est presque un BP. Non : un MP interdit precisement cette position.
  • Piege 2 : oublier qu'une ligne 1 BP / 0 MP elimine tous les autres elements de la ligne.
  • Piege 3 : conclure sur une ligne sans la croiser avec les autres.
  • Piege 4 : ne pas revenir en arriere quand une ligne contredit une hypothese.
  • Piege 5 : ne pas verifier le code final sur chaque ligne.

8. Strategie de vitesse

  • 0 a 10 secondes : chercher les lignes a 0 et barrer les elements absents.
  • 10 a 25 secondes : reperer les lignes qui partagent des chiffres.
  • 25 a 45 secondes : placer les BP certains et noter les positions interdites des MP.
  • Fin : tester les 1 ou 2 codes possibles sur toutes les lignes.
Automatisme : barrer les absents → surligner les presents → interdire les mauvaises positions → croiser les lignes → verifier.
