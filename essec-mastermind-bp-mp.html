1. Objectif du chapitre

Dans un Mastermind, on cherche un code secret. Chaque ligne propose un code possible et donne deux informations : le nombre de chiffres bien places et le nombre de chiffres mal places.

Ces informations sont exactes. Une ligne ne dit pas qu'un chiffre est “peut-etre” correct : elle impose une contrainte precise. La solution est le seul code qui respecte toutes les lignes en meme temps.

Idee centrale : on ne devine pas. On trie les chiffres : absents, presents, positions interdites, positions certaines.

2. Comprendre BP / MP

BP = bien place

Le chiffre est dans le code et exactement a cette position.

MP = mal place

Le chiffre est dans le code, mais pas a cette position. Sa position actuelle est interdite.

BP + MP

C'est le nombre total de chiffres de la ligne qui appartiennent au code.

Le reste

Les chiffres non comptes dans BP + MP sont absents du code.

Lecture des indicesAutomatisme
IndiceSignification exacte
0 BP / 0 MPAucun chiffre de la ligne n'est dans le code.
1 BP / 0 MPUn seul chiffre est present et il est bien place. Les autres sont absents.
0 BP / 1 MPUn seul chiffre est present mais il doit changer de position. Les autres sont absents.
1 BP / 1 MPDeux chiffres sont presents : un bien place, un mal place. Le troisieme est absent.
0 BP / 2 MPDeux chiffres sont presents et tous les deux sont mal places.

3. La methode de tri

La bonne methode consiste a tenir une sorte de brouillon mental. On barre les chiffres impossibles, on conserve les chiffres presents, puis on interdit certaines positions.

1
Compter les presents

Dans chaque ligne, BP + MP donne le nombre de chiffres presents.

2
Eliminer

Avec 0 BP / 0 MP, on elimine toute la ligne. Avec 1 BP / 0 MP, on sait que les deux autres chiffres sont absents.

3
Interdire les positions MP

Un chiffre MP est certain, mais il n'est pas a la position indiquee.

4
Croiser les lignes

Quand un chiffre apparait dans plusieurs lignes, on regarde s'il peut satisfaire les contraintes des deux lignes.

5
Verifier

Le code final doit redonner exactement les BP et MP de chaque ligne.

Code : 468. Verification : chaque ligne redonne exactement les indices annonces.

5. Exemple complet : raisonner par hypothese

Code a 3 chiffresSolution : 643
PropositionIndice
1231 BP / 0 MP
3411 BP / 1 MP
2461 BP / 1 MP

Ligne 1 : un seul chiffre parmi 1, 2, 3 est present et bien place. On teste les trois hypotheses.

Si 1 etait bien place, alors 2 et 3 seraient absents. La ligne 341 contiendrait alors seulement 4 et 1 : il faudrait 1 BP / 1 MP, mais 1 est mal place dans 341. Cela bloque.

Si 2 etait bien place, alors 1 et 3 seraient absents. La ligne 246 aurait 2 bien place, mais il faudrait encore un MP parmi 4 ou 6. Les croisements rendent cette piste impossible.

Si 3 est bien place, alors 1 et 2 sont absents. Dans 341, le 4 est bien place en position 2 et le 3 est mal place. Dans 246, le 6 est mal place et le 4 est bien place. On obtient 643.

A retenir : quand une ligne laisse plusieurs choix, on teste une hypothese puis on verifie toutes les lignes. Une seule contradiction suffit a l'abandonner.

6. Pieges classiques

  • Piege 1 : croire qu'un MP est incertain. Non : un MP est present avec certitude, mais mal place.
  • Piege 2 : oublier que BP + MP donne le nombre total de chiffres presents.
  • Piege 3 : utiliser une ligne 1 BP / 0 MP sans eliminer les deux autres chiffres.
  • Piege 4 : trouver un code qui respecte certaines lignes mais pas toutes.
  • Piege 5 : confondre “deux chiffres corrects mal places” avec “deux chiffres corrects dont un bien place”.
Automatisme final : compter les presents → eliminer → interdire les positions MP → placer les BP → verifier toutes les lignes.
